# 変更・復旧・検証をつなげて読む

このディレクトリは、4 repository をまたぐ Account リリースの流れを学ぶ入口です。コード、Git の配備定義、実際の稼働状態を別々に確認する理由を説明します。各 repo のファイル案内と合わせて読んでください。

## 構成と読む順番

| ファイル | 担当する説明 | 読みたいとき |
| --- | --- | --- |
| [release-tracing.md](release-tracing.md) | 変更から CI、イメージ、manifest PR、二段階の Argo CD 同期、Pod までの追跡。 | 「この Pod はどの変更からできたのか」を調べるとき。 |
| [incident-recovery.md](incident-recovery.md) | 症状を読み取りで調べ、復旧操作と成功確認を分ける手順。 | リリースが止まった、結果が分からない、前版へ戻したいとき。 |
| [verification-scenarios.md](verification-scenarios.md) | 正常系・異常系の目的、観測点、合否、後片付け。 | 試験計画や結果を読んで、どこまで確認できたか判断するとき。 |

通常の変更入口は [現在の配備契約](../../learning/existing-kind/DEPLOYMENT.md) に従う Git PR と Argo CD 同期です。この教材は、新しい実機操作、認証情報の発行、権限変更を承認するものではありません。**状態を変える手順には「状態変更」と表示**しています。実行前に対象、差分、権限、復旧方法を確認します。

## この文書の根拠と確認範囲

2026-10-25 に、保存されているコード、GitOps 定義、公開 PR / CI と、進行中の PLAT-199 検証担当から共有された結果を整理しました。文書作成のための実機試験は行っていません。

| 根拠 | この文書で言えること | それだけでは言えないこと |
| --- | --- | --- |
| 固定 commit のコード・Chart | 想定する処理、判定条件、所有する設定。 | 稼働環境でその処理が成功したこと。 |
| 公開 CI・manifest PR | 検査の成否、イメージの由来、Git に入った差分。 | GHCR への公開、Argo の適用完了、実際の配信比率。 |
| 検証担当の共有結果 | 欠測による停止、Collector の Git 復元、timeout 後の同一要求の照合結果。 | 最終復旧、全体非回帰、一時権限の撤去まで完了したこと。 |

確認済みの個別結果と未完了部分は [結果の記録](verification-scenarios.md#今回共有された結果) にまとめています。検証担当の生ログはこの教材へ公開していません。公開 CI の結果とは区別して扱います。過去の PLAT-170 / 171–176 の完了記録も、今回の受入完了の根拠にはしません。

実装の参照先は各文書の固定 SHA のリンクです。将来使うときは、現在のコード・配備契約との差分を確認してください。artifact の保存期限や token の有効期限があるため、当時の成功を現在の実行許可や利用可能性と読み替えないでください。

## 記録の残し方

Git には、対象 commit、目的、操作、観測結果、判断、未確認点を Markdown で残します。ログや生成 JSON は [学習記録の方針](../learning-workflow.md) に従います。秘密値、実 UID / IP、内部絶対パス、非公開実行 ID、実測容量は公開文書へ載せません。実体の照合に必要な情報は、承認された非公開の証拠で確認します。
